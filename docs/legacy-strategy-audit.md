## 旧代码中需要避免的问题

1. 平仓函数先覆盖 `entry`，再计算收益。因此记录的进出场价相同、逐笔 PnL 为零。
2. 策略直接使用当前 K 线与当前价格做决策，若在回测中按同根 K 线成交，会产生前视偏差。
3. 多处固定使用 `rb2410`、`jm2409` 等已到期合约；真实研究必须使用有明确规则的连续合约数据。
4. `max(1, ...)` 在资金不足一手时仍强制开仓，可能超过风险预算。
5. 策略状态文件依赖启动目录；而 VeighNa 批处理文件切换到桌面根目录，和脚本所在子目录不一致。

## 已读取的结果为何不能采信

`adapt_result.json` 的焦煤 `DCE.jm2409` 回测记录了 -0.85% 的账户变化、2 次交易，
但两笔逐笔 PnL 都为 0，正好印证了上述收益记账问题。`backtest_result.json` 记录
螺纹钢 0 笔交易、0% 收益。这些文件可保留为迁移前基线，不能作为策略有效性的证据。

## 迁移原则

- 先用无账户回测核心验证策略；每一次成交均保留时间、方向、价格、数量和成本。
- 只在样本外测试、参数敏感性检查和模拟交易均通过后，才考虑 TqSdk 或 VeighNa 适配。
- 账户、密码、CTP/TTS 连接配置永远放在项目外部且不提交版本库。
